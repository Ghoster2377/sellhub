# ⚡ SellHub — единая панель продаж FunPay + Playerok

Одно окно для торговли на нескольких игровых площадках: **заказы, чаты, товары,
цены конкурентов, аналитика и автоматизация** (автовыдача, автопрайс, автоответы).

Сейчас в проекте: рабочий каркас «клиент–сервер» и **реализована фаза 1 —
настоящие подключения FunPay и Playerok**: заказы, чаты, ответы покупателям
и действия по сделкам прямо из панели (автовыдачу сознательно пока не делали).
**Демо-данных в проекте больше нет**: заказы, чаты, суммы и уведомления берутся
только с реальных FunPay и Playerok. Если площадка не подключена, её цифры
равны нулю, а не нарисованы.

```
Браузер (frontend/index.html)
   │  GET /api/state · POST /api/action · WS /ws
   ▼
FastAPI-бэкенд (backend/main.py) ── Store: единое состояние (backend/store.py)
   │
   ├── адаптер FunPay   ✅ (фаза 1) — golden key + polling /runner/   [aiosellers]
   ├── адаптер Playerok ✅ (фаза 1) — токен + GraphQL + WebSocket     [aiosellers]
   ├── заглушка (BaseAdapter)     — ничего не делает, данных не выдумывает
   └── (потом) GGsel — официальный Seller API · Telegram-бот · SQLite/Postgres
```

## 🚀 Быстрый старт (локально)

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Открыть http://localhost:8000 — панель в live-режиме.
Откройте две вкладки: перетащите заказ в одной — во второй он переместится сам.

> `frontend/index.html` без сервера покажет пустую панель и сообщение
> «Сервер недоступен» — никаких выдуманных заказов и сообщений.

### Docker

```bash
docker build -t sellhub .
docker run -d -p 8000:8000 --restart unless-stopped sellhub
```

## 🌍 Где хостить (сайт или приложение)

| Площадка | Что можно | Цена | Как |
|---|---|---|---|
| **GitHub Pages** | Только статичный фронтенд (демо-панель без сервера) | бесплатно | Settings → Pages → ветка `main`, папка `frontend/` (или выложить `index.html` в корень). Живых заказов не будет — нужен бэкенд |
| **Render.com / Railway / Fly.io** | Полное приложение (Docker) | есть бесплатные тарифы | New → Web Service → подключить репозиторий GitHub → Dockerfile. Деплой автоматически при каждом `git push` |
| **VPS** (Timeweb, Aeza, Selectel…) | Полное приложение 24/7 — **рекомендуется** для автовыдачи | от ~200 ₽/мес | `docker compose` или `uvicorn` + автозапуск systemd; SSH-доступ, свой домен по желанию |
| **Свой ПК** | Полное приложение, пока ПК включён | 0 ₽ | Запуск через Docker/uvicorn + автозапуск |
| **GitHub Actions** | CI/CD: тесты и автодеплой на Render/VPS при push | бесплатно | `.github/workflows/deploy.yml` (добавим в фазе 4) |
| **Десктоп-приложение** | `.exe` для Windows из этого же кода | 0 ₽ | Tauri/Electron оборачивает `frontend/`, бэкенд — локальным процессом (фаза 4) |

**Итог:** код живёт на GitHub → GitHub Pages годится только для витрины-демо →
для настоящей панели (которая 24/7 слушает FunPay и Playerok) нужен любой
постоянно включённый хостинг: бесплатный Render или дешёвый VPS.

## 🌐 Сайт на GitHub Pages — публикуется автоматически

В репозитории уже есть воркфлоу `.github/workflows/pages.yml`: при каждом push
в ветку `main` GitHub сам публикует сайт из папки `frontend/`.

1. Запушьте проект в свой репозиторий (команды выше).
2. В репозитории: **Settings → Pages → Source: GitHub Actions** (один раз).
3. Через 1–2 минуты (прогресс виден во вкладке **Actions**) открывайте
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Статичная страница без бэкенда покажет только пустой каркас панели: реальные
заказы FunPay/Playerok приходят с сервера. Для настоящих данных деплойте этот
же репозиторий на Render (бесплатно) или VPS через Dockerfile.

## 🖥 Приложение для Windows (.exe) — собирается в облаке

В папке `desktop/` — Electron-обёртка (та же панель, что и сайт), а
`.github/workflows/desktop.yml` собирает её на Windows-раннере GitHub —
сам GitHub соберёт приложение, ничего устанавливать для сборки не нужно.

**Сборка через GitHub:**
1. Репозиторий → вкладка **Actions** → воркфлоу **Desktop build (Windows .exe)** →
   **Run workflow** (либо запушьте тег: `git tag v0.1.0 && git push --tags`).
2. После сборки (~5–10 минут) внизу запуска в разделе **Artifacts** скачайте
   `SellHub-Windows`.
3. В архиве будут `SellHub Setup 0.1.0.exe` (установщик) и `SellHub 0.1.0.exe`
   (портативная версия — просто запустить).

**Локально (если установлен Node.js):**

```bash
cd desktop
npm install
npm start
```

Приложение открывает ту же панель; без сервера она пустая и сообщает об ошибке подключения.

## 🔑 Подключение реальных площадок — фаза 1 реализована ✅

Панель получает **настоящие заказы и чаты** FunPay и Playerok через библиотеку
`aiosellers` (FunPay: golden key + polling `/runner/`; Playerok: токен +
GraphQL/WebSocket — те же механизмы, что используют популярные боты;
все действия — под вашу ответственность).

### Где взять ключи

* **FunPay — Golden Key**: войдите на funpay.com → F12 (DevTools) → Application →
  Cookies → скопируйте значение `golden_key`. Заодно возьмите User-Agent этого
  браузера (DevTools → Network → Request Headers → user-agent) и укажите его
  при подключении — иначе FunPay может сбросить сессию.
* **Playerok — Access-токен**: playerok.com → F12 (DevTools) → Network →
  любой запрос `graphql` → скопировать значение заголовка `Authorization`.

### Два способа подключить

1. **Прямо из панели**: Настройки → вставить ключ → «Подключить».
   При успехе появится имя аккаунта, и заказы с чатами сразу начнут загружаться.
2. **На сервере**: скопировать `.env.example` в `.env` и вписать ключи —
   подключение произойдёт автоматически при старте. Ключи, введённые через
   панель, сохраняются в `data/credentials.json` (файл в `.gitignore`,
   в репозиторий не попадает).

### Что уже работает с реальными данными

* заказы обеих площадок в едином канбане — статусы синхронизируются вживую;
* все чаты в едином инбоксе — **ответ из панели уходит прямо на площадку**;
* Playerok: кнопка «Выдать» вызывает `deal.complete()`, «Подтвердить завершение» — `deal.confirm()`;
* FunPay: «Возврат» вызывает настоящий `refund`; «Выдан/Завершён» — локальные
  отметки (реальный статус меняет покупатель/площадка, он синхронизируется событиями);
* уведомления о новых заказах, сообщениях и отзывах;
* автопереподключение при обрыве связи (каждые 30 с) и понятные ошибки ключей;
* демо-данных нет вовсе: неподключённая площадка даёт нули, а не выдуманные сделки.

### Чего пока нет (следующие фазы)

Автовыдача из склада (по вашей просьбе отложена), реальные товары/цены/конкуренты
(фаза 2), Telegram-уведомления (фаза 2), аналитика по реальным сделкам и БД (фаза 3).

## 📁 Структура проекта

```
sellhub/
├── frontend/index.html        # вся панель: дашборд, канбан заказов, инбокс чатов,
│                              # аналитика, настройки, редактор оформления
├── backend/
│   ├── main.py                # FastAPI: REST + WebSocket + статика + вход по коду из Telegram
│   ├── store.py               # единое состояние: только реальные данные площадок
│   ├── manager.py             # подключение площадок, ключи, автопереподключение
│   ├── demo_data.py           # стартовое (пустое) состояние + комиссии площадок
│   └── adapters/
│       ├── base.py            # контракт адаптера (единая модель событий)
│       ├── funpay.py          # РЕАЛЬНЫЙ FunPay: заказы, чаты, сообщения, refund
│       └── playerok.py        # РЕАЛЬНЫЙ Playerok: сделки, чаты, complete/confirm
├── desktop/                   # десктоп-обёртка Electron: main.js, package.json
├── .github/workflows/         # pages.yml — автопубликация сайта, desktop.yml — сборка .exe
├── requirements.txt · Dockerfile · .gitignore · README.md
```

## ⚠️ Дисклеймер

Проект не аффилирован с FunPay и Playerok. Автоматизация использует
неофициальные механизмы площадок и может нарушать их правила — оценивайте
риски сами. Ключи хранятся на вашем сервере и отправляются только на сами площадки.
